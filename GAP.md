# Tesla API coverage (gap analysis)

What Tesla offers third-party apps, what this server covered before this change, and what it covers now.
Audited 2026-10-29 against:
- Tesla's Go library [`teslamotors/vehicle-command`](https://github.com/teslamotors/vehicle-command) at v0.4.1
  (`49977a18`, the commit `conformance/run.sh` pins): every command in `pkg/vehicle`, `pkg/proxy/command.go`
  (the Fleet REST name for each), `cmd/tesla-control`, and the `car_server.proto` / `vcsec.proto` messages.
- The Fleet API docs at developer.tesla.com: vehicle endpoints, vehicle commands, vehicle management, charging,
  energy, user, and partner endpoints, and the authentication (scopes) page.

"Present before" means the `main` tool surface this branch started from (`357b38f`: list, status, wake, lock,
auth status, audit). A capability is a distinct thing a caller can make Tesla do or tell. Variants that are one
tool here (sentry on/off) count separately when they are separately gated.

## How each capability is reached

- **Signed (Vehicle Command Protocol).** Every command Tesla's `vehicle-command` can sign is sent as a signed
  `signed_command`, in the domain Tesla uses: VCSEC for lock, unlock, remote start, trunk, frunk, tonneau, and
  auto-secure; infotainment (CarServer) for everything else. Payloads are hand-encoded in
  `src/tesla/vcp/payloads.ts`. All 80 payload vectors in `test/vectors/vcp-commands.json` are byte-identical to
  what Tesla's own `pkg/vehicle` methods build: `conformance/go/tesla_mcp_commands_test.go` swaps in a capturing
  dispatcher and calls them. Infotainment requests ask for an encrypted reply (Tesla's default flags), and a
  plaintext reply is refused. The infotainment handshake, signature, request hash, and AES-GCM reply are checked
  against Tesla's Signer and Verifier (`test/vectors/infotainment-honk.json`).
- **Fleet REST.** Data endpoints, energy, account, sharing, Fleet Telemetry, and the five vehicle commands that
  have no protocol message (navigation and Boombox; Tesla's own proxy forwards these to REST too). Every path
  comes from a fixed template in `src/tesla/endpoints.ts`. There is no generic proxy.

## Naming and gating decisions

- **Names:** `tesla_<subject>_<verb or setting>` in snake_case: `tesla_charge_set_limit`, `tesla_seat_heater_set`,
  `tesla_windows_vent`. Energy tools start with `tesla_energy_`, account tools with `tesla_account_`, other
  vehicle REST tools with `tesla_vehicle_`. The six existing tool names are unchanged.
- **Inputs:** every input schema is strict (unknown arguments are rejected). Vehicle tools take an optional
  `vehicle_id` and energy tools an optional `energy_site_id`; either can be left out when the account has only
  one. Parameters are typed enums and ranges (seat names, `low`/`medium`/`high`, 50-100 %), not Tesla's raw
  integers, and are checked again by the payload builder before anything is signed.
- **Confirmation:** every tool that changes a vehicle or energy product requires `confirm: true` and supports
  `dryRun: true`. Refusals and dry runs are audited. Read tools take neither. Two tools that only read are
  `POST`s or signed messages under the hood (`tesla_vehicle_fleet_status`, `tesla_vehicle_ping`); they change
  nothing and stay ungated.
- **Never waking the car:** read tools never wake it; an asleep car reports `vehicle_asleep`. Signed commands
  other than lock do not wake it either: they fail with `vehicle_asleep` and say to call `tesla_wake`, so waking
  stays an explicit, confirmed step. `tesla_vehicle_data_cached` reads the last reported data without
  contacting the car at all.
- **Dangerous commands:** anything that unlocks, opens, starts, or weakens security is tagged with a
  `dangerousAction` and is not registered unless `DANGEROUS_COMMANDS_ENABLED` is exactly `"true"`. That covers
  unlock, remote start, trunk/frunk/tonneau open, window and sunroof vent, charge port open (it also unlatches a
  cable), Sentry Mode off, Valet Mode, PIN to Drive, Speed Limit Mode, Guest Mode, erase user data, HomeLink,
  scheduling a software update (the car cannot be driven while it installs), and creating a share invite (it
  grants access to the car). Closing things, turning Sentry on, and stopping a tonneau stay safe. `OwnerState`
  checks the flag again before sending, so a tool registered by mistake still cannot act.
- **Errors:** a 403 names the scope the tool needs. A car's own refusal reason (`is_charging`, `already_set`) is
  passed through as `carReason`.

## OAuth scopes: what the app requests vs. what tools need

**What the app requests today.** The Worker never requests scopes itself: it refreshes a token whose scopes
were fixed when the owner signed in. The only scope lists in the repository are in the README:
- Step 1 (developer app): `openid offline_access vehicle_device_data vehicle_cmds`
- Step 6 (partner token for registration): `openid vehicle_device_data vehicle_cmds`

This change does not alter either list.

**What each tool needs.** Tesla's current endpoint pages no longer print a per-endpoint scope line. The mapping
below follows Tesla's scope definitions (authentication overview) and its earlier per-endpoint lists. Each
tool's description names its scope, and a 403 error repeats it.

| Scope                                   | Requested today          | Tools that need it                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vehicle_device_data`                   | yes                      | 19 tools: 18 vehicle reads (list, status, data, cached data, mobile access, nearby chargers, alerts, release notes, service, fleet status, options, warranty, two eligibility lists, drivers, invites, Fleet Telemetry config and errors) and `tesla_vehicle_fleet_telemetry_config_delete`; it also satisfies `tesla_account_products` |
| `vehicle_cmds`                          | yes                      | 70 tools: `tesla_wake`, `tesla_lock`, `tesla_vehicle_ping`, the 59 non-charging signed commands, the 5 REST commands (navigation, Boombox), driver removal, and share invite create/revoke; it also satisfies the 14 charging commands                                                                                                  |
| `vehicle_location`                      | **no**                   | `tesla_vehicle_data` with `location_data` (also needs `vehicle_device_data`)                                                                                                                                                                                                                                                            |
| `vehicle_charging_cmds`                 | **no**                   | `tesla_vehicle_charging_history` (the 14 charging commands accept it or `vehicle_cmds`)                                                                                                                                                                                                                                                 |
| `user_data`                             | **no**                   | `tesla_account_me`, `tesla_account_region`, `tesla_account_orders`, `tesla_account_feature_config`                                                                                                                                                                                                                                      |
| `energy_device_data`                    | **no**                   | 9 energy read tools (live status, site info, site status, backup time, energy/backup/charge history, charger live status, tariff)                                                                                                                                                                                                       |
| `energy_cmds`                           | **no**                   | 6 energy settings tools (backup reserve, operation mode, Storm Watch, grid import/export, off-grid vehicle reserve, time of use)                                                                                                                                                                                                        |
| `vehicle_specs`, `vehicle_pricing_info` | no (partner tokens only) | none: specs and pricing are not implemented                                                                                                                                                                                                                                                                                             |
| `enterprise_management`                 | no (business)            | none: enterprise endpoints are not implemented                                                                                                                                                                                                                                                                                          |

So with the scopes requested today, **20 tools cannot succeed**: 9 energy reads, 6 energy settings, 4 account
tools, and charging history. `tesla_vehicle_data` also fails when it asks for `location_data`. They are still
registered: they are generic, a self-hoster may grant those scopes, and each one fails with a clear `forbidden`
error that names the scope. Getting them working needs a new sign-in with the added scopes (and the developer
app allowed to request them); no code change.

## Not implemented, and why

| Capability                                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `parental_controls_activate`, `_deactivate`, `_clear_pin_admin`, `_enable_setting`, `_set_speed_limit`                         | The docs name no body fields (only "setting and enable") and vehicle-command v0.4.1 has no protocol message for them. Guessing PIN and limit fields for a driving restriction is not acceptable. Speed Limit Mode covers the speed cap.                                                                                                                               |
| `remote_steering_wheel_heat_level_request`, `remote_auto_steering_wheel_heat_climate_request`                                  | Bodies undocumented, no protocol message. On/off steering wheel heat is implemented.                                                                                                                                                                                                                                                                                  |
| `sun_roof_control` `stop`                                                                                                      | No protocol message exists. Vent and close are implemented.                                                                                                                                                                                                                                                                                                           |
| `upcoming_calendar_entries`                                                                                                    | The payload is the Tesla app's calendar-sync format, which is undocumented.                                                                                                                                                                                                                                                                                           |
| Key management (`add-key`, `add-key-request`, `remove-key`, `rename-key`, `list-keys`)                                         | Adding a key needs an NFC key-card tap in the car (BLE). Removing or renaming keys remotely weakens security and could revoke this server's own key. The key count is in `tesla_vehicle_fleet_status`.                                                                                                                                                                |
| `state`, `body-controller-state`, `session-info` over the protocol                                                             | BLE-oriented in `tesla-control`; `vehicle_data` and `vehicle_data_cached` cover the same data over Fleet.                                                                                                                                                                                                                                                             |
| Managed charging (`set_managed_charge_current_request`, `set_managed_charger_location`, `set_managed_scheduled_charging_time`) | Business fleet features, not in the public docs.                                                                                                                                                                                                                                                                                                                      |
| Raw `get` / `post` (`tesla-control`)                                                                                           | A generic proxy, refused by design.                                                                                                                                                                                                                                                                                                                                   |
| `charging_invoice`                                                                                                             | Returns a PDF; these tools return JSON.                                                                                                                                                                                                                                                                                                                               |
| `charging_sessions`                                                                                                            | Business accounts only.                                                                                                                                                                                                                                                                                                                                               |
| `specs`, `pricing`                                                                                                             | Partner tokens only (`vehicle_specs`, `vehicle_pricing_info`); specs is billed per call.                                                                                                                                                                                                                                                                              |
| `enterprise_payer`, `enterprise_roles`                                                                                         | `enterprise_management` scope, business accounts.                                                                                                                                                                                                                                                                                                                     |
| `share_invites redeem`                                                                                                         | Redeeming joins _another_ owner's car; the body is undocumented.                                                                                                                                                                                                                                                                                                      |
| `fleet_telemetry_config` create, `fleet_telemetry_config_jws`                                                                  | Needs a configuration signed with the command key (a Tesla.SS256 Schnorr JWS) and a running telemetry server with its CA. That is infrastructure to set up, not a tool. Reading and deleting the config are implemented.                                                                                                                                              |
| Partner endpoints (`register`, `public_key`, partner `fleet_telemetry_errors`, `fleet_telemetry_error_vins`)                   | They need a **partner token**: a client-credentials token that acts as the application for every customer, not as the owner. The Worker only ever holds the owner's token, and adding partner authority to an owner-facing MCP would widen what a leaked bearer token can do. Registration is a one-time setup step and stays the documented `curl` in README step 6. |
