# tesla-mcp review findings (2026-10-29)

Reviewed at `main` 0cd8ab1. Baseline: `npm run check` green (84 tests). Go is not installed on this host, so
`conformance/run.sh` was not run locally (CI's `go-conformance` job runs it). This change does not touch the signer.

Not committed. Severity: Critical / High / Medium / Low.

## (a) Our own routine hard-coded in the MCP

| #   | Severity | Finding                                                                                                                                                                                                                                                                                                                                            |
| --- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | High     | **The nightly lock lives inside the server.** `OwnerState.alarm()`, `ensureAlarm()`, `NightlyRun`, `MISSED_WINDOW_MS` (3 h), `MAX_NIGHTLY_RUNS` (4), the catch-up-after-outage rule and `finishNightly`/`last_run` (about 200 lines of `src/owner/state.ts`) are one owner's routine, not a Tesla tool.                                            |
| A2  | Medium   | **The schedule is shipped as config.** `NIGHTLY_LOCK_ENABLED=true`, `NIGHTLY_LOCK_TIME=22:00`, `NIGHTLY_LOCK_TIMEZONE=America/New_York` in `wrangler.jsonc` and `Env`. It is also the only place the "sign-in needs renewing" state is shown.                                                                                                                                                                                                    |

## (b) Other issues

| #   | Severity | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B1  | Critical | **Re-seeding after `reauth_required` does not reliably work.** `loadTokens` only applies a new `TESLA_BOOTSTRAP_REFRESH_TOKEN` when no tokens are stored or `auth_state=reauth_required` was persisted. Only the OAuth-refresh rejection persists that state. A Fleet 401 after a forced refresh (`withToken`) reports `reauth_required` but persists nothing, and a signed-command 401 is reported as `command_failed`. In both cases the stored (useless) tokens block any new bootstrap token, so `wrangler secret put` silently does nothing. There is no test for re-seeding at all, and no documented one-step procedure. Since the refresh token was revoked on 2026-10-25 the nightly lock has failed every night. |
| B2  | High     | **Failures are silent.** A failed nightly lock is written only to the Durable Object's audit table and `last_run`. Nothing is logged and nothing alerts. Four nights failed with nobody told.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| B3  | High     | **PR auto-merge.** `pr-auto-merge.yml` squash-merges any green same-repo PR and requires only `verify` (not `secret-scan` or `go-conformance`). On a repo that controls a car, that defeats review and phased rollouts like this one. Not changed in this PR because it is an explicit owner rule. This PR is opened as a **draft** so the helper holds it. Recommendation: require every check and opt in with a label.                                                                                                                                                                                                                                                                                                   |
| B4  | Medium   | **Lock failures collapse to `command_failed`.** A caller cannot tell `pairing_required`, `wake_timeout`, `rate_limited`, or `unauthorized` apart without reading the prose. A signed-command 401 that survives a forced refresh should be `reauth_required`.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| B5  | Medium   | **Errors swallowed.** `createMcpServer` turns every thrown error into `internal_error` and logs nothing, so a server bug cannot be diagnosed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| B6  | Medium   | **Test gaps.** No re-seed-after-reauth test. No test of `tesla_lock` waking an asleep car through MCP. No read-back of the lock state. No outside caller. Go conformance only runs in CI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| B7  | Low      | **Auth is sound.** SHA-256 of both values, then a constant-time compare. Fails closed when `MCP_BEARER_TOKEN` is unset or empty. The header regex is bounded. Minor: there is no minimum token length (a 1-character token would be accepted). Recommend refusing tokens shorter than 32 characters in a later change. Not enforced here, so the rollout cannot lock out the existing clients.                                                                                                                                                                                                                                                                                                                             |
| B8  | Low      | **Confirm/dryRun gate is sound.** `confirm` is checked before `dryRun`, both are audited, and refusals send nothing. Minor: `dryRun` needs `confirm: true` too; `dryRun` does not check the vehicle id against the account despite "check the request"; a dry run is audited with outcome `ok`.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| B9  | Low      | **Secrets handling is sound.** Tokens use AES-256-GCM with AAD, refresh-token rotation is persisted first, audit details are redacted, and the only `console` call logs codes. The used bootstrap token stays in Worker secrets after seeding (it is dead after the first rotation, so the exposure is small).                                                                                                                                                                                                                                                                                                                                                                                                             |
| B10 | Low      | **Leftovers from tescmd-mcp/Hermes.** The `/callback` placeholder page (keep it: it is the registered Tesla redirect URI). `scripts/vcsec_vectors.py` needs `hermes-tescmd-plugin` (keep it: it regenerates the cross-check vectors; describe it neutrally).                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| B11 | Low      | **CI is sound.** It uses `pull_request`, `contents: read`, SHA-pinned actions, and skips fork PRs on the self-hosted runner. See B3 for auto-merge.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| B12 | Low      | **Overlap in phase A.** The alarm and an outside caller both firing at 22:00 serialize on the owner's command lane. The second sends a lock to a locked car, which is harmless.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
