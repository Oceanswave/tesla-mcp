# Security

## Reporting a vulnerability

Report vulnerabilities privately through GitHub's
[private vulnerability reporting](https://github.com/Oceanswave/tesla-mcp/security/advisories/new). Do not open a
public issue. Include what you found, how to reproduce it, and its impact. You will get an acknowledgement, and a
fix or mitigation will be coordinated with you before any disclosure.

## Threat model summary

This server can command a real car (and change energy-product settings) and read their status, so the assets are
the owner's Tesla account tokens, the vehicle-command private key, control of the car, and the owner's data,
including location when the token allows it.

| Threat                                 | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unauthorized MCP caller                | `/mcp` requires the static bearer token (compared in constant time, SHA-256 of both values) or an access token issued by the server's OAuth front door for that exact resource, from a client that still exists. OAuth tokens, codes, and client secrets are stored only as hashes; refresh tokens rotate. `/authorize` requires PKCE S256 and the `OAUTH_ADMIN_PASSPHRASE` (constant-time compare, refused while unset), behind a single-use approval token bound to the request and a limit of 5 wrong passphrases per IP per 15 minutes. Redirect URIs must be Claude's callbacks, loopback, or listed in `OAUTH_EXTRA_REDIRECT_URIS`. Static clients are managed with the static bearer token, and deleting one revokes its tokens. |
| Assistant acts without the user asking | Every state-changing tool requires `confirm: true`; `dryRun` describes without acting. Refusals are audited.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Harmful commands                       | Anything that unlocks, opens, starts, or weakens security (unlock, remote start, openings, Sentry off, valet/PIN/speed limit, guest mode, HomeLink, erase, software update, share invites) is only registered when `DANGEROUS_COMMANDS_ENABLED` is `"true"` (default off), and the Durable Object refuses to send it otherwise. The signer builds only the payloads in `SIGNED_COMMANDS`; REST calls only reach the paths in `src/tesla/endpoints.ts`.                                                                                                                                                                                                                                                                                  |
| Sign-in tampering                      | `/login` stores a random single-use `state` (10-minute expiry) with the redirect URI it sent; `/callback` consumes it before anything else and exchanges the code with that same redirect URI. Once any token has named the account (`sub` of the access token, kept across re-seeds), `/callback` only accepts that Tesla account, so a stranger who runs the public flow cannot swap in their account; a bootstrap token not used yet is tried first. A server that has never held a token trusts its first sign-in. Sign-in pages never show the code or tokens, and escape everything they print.                                                                                                                                   |
| Token theft from storage               | Tesla tokens are AES-256-GCM encrypted (random IV, purpose-bound AAD) with a key held only in Worker secrets.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Secrets leaking into logs or audit     | Logs carry only error codes and protocol stages. Audit details are internally generated codes, additionally redacted for token-shaped strings. Location is only requested when a caller asks `tesla_vehicle_data` for `location_data` (and the token has `vehicle_location`); it is never logged or audited.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Refresh-token loss or replay storms    | Load, seeding, and refresh are single-flight; seeding never overwrites newer tokens. The rotated refresh token is persisted before use. A rejected refresh token stops all refreshes (`reauth_required`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Forged or replayed vehicle responses   | The VCP session handshake is authenticated with the session-info HMAC and bound to the request UUID; commands use a monotonic counter and short expiry. Responses must echo the request UUID.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Key mismatch or misconfiguration       | The private key must match the published public key (checked by signing and verifying) before any command is signed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Request smuggling of large bodies      | `/mcp` bodies are capped at 64 KiB; upstream Tesla responses are size- and time-bounded; redirects are not followed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

Known limitations of the MVP: one owner identity, so the static bearer token and every approved OAuth client can use
every registered tool (there are no scopes per client); the passphrase limit is kept in KV, which is eventually
consistent, so a burst spread across locations can get a few more tries; VCSEC replies are not encrypted by the vehicle, so VCSEC results are reported as Tesla
returns them (infotainment replies must be encrypted and are authenticated); if a token refresh response is lost in transit
after Tesla rotated the refresh token, the owner must sign in again (open `/login`, or
`npx wrangler secret put TESLA_BOOTSTRAP_REFRESH_TOKEN`; any value not seeded before replaces the stored tokens).

CI runs pull request code on a self-hosted runner; the repository requires maintainer approval before any workflow
run from an external contributor.
